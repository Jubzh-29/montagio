# Build log

A dated record of how Montagio is built during the challenge window.

## 2026-10-17

- Repository created. Monorepo scaffold (npm workspaces, TypeScript, Vitest), licenses (AGPL-3.0 / Apache-2.0 / CC-BY-4.0), DCO contribution rules, CI.
- Preset format v0.1, model registry and weight lock, preset → ComfyUI workflow compiler.
- Library content: 3 provisional presets (Crash Push, Slow Push, Pan Left), 3 models (Wan 2.2 Fun Camera, Wan 2.2 5B, Z-Image Turbo).
- **Provisional:** `workflows/*.api.json` are hand-written templates and `registry/models.lock.yaml` holds repository-level URLs. Both are replaced after GPU session S1 by workflows exported from a running ComfyUI and by exact file URLs + sha256, with every license re-read at the source.
- Studio screen (monitor with viewfinder marks, camera-move glyphs, model picker with licenses, REC tally accent), open-stack page, EN/FR, demo mode end to end with Playwright.
- Sequence package: FFmpeg helpers for the last frame, the montage and the 9:16 cut.
- Sequences API: 2-3 shots chained from each shot's last frame (poll-driven state machine, resumable montage), 16:9 film and 9:16 cut.
- Sequence mode in the Studio: pick 2-3 camera moves in order, watch shot-by-shot progress, download the 16:9 film or the 9:16 cut.
- GPU session tooling (`infra/runpod/`): pod bootstrap (ComfyUI v0.41.0 with `--disable-partner-nodes`, comfy-api-proxy 0.1.6, pinned PyTorch and Node.js), weight downloader that resolves exact Hugging Face files, checks sha256 and proposes a lock patch, and an SDK smoke test with timing and VRAM. `check-open-stack` now scans `infra/` and catches the SDK's Router namespace (`comfy.models.*`). Session guide: `docs/S1_CHECKLIST.md`.
- ComfyUI node pack (`comfy-nodes/`, GPL-3.0-only): "Load Montagio Preset" and "Montagio Preset from YAML" turn a preset into the inputs of `WanCameraEmbedding`, `CLIPTextEncode` and `CreateVideo`. Tests run in CI and compare the pack with the app's own `parsePreset`/`compileJob`. Registry publishing is a manual workflow only; `PublisherId` and `Repository` are still TODO.
- Preset check on the command line: `npm run montagio -- preset validate <file|folder>` checks the schema, the models a preset names, the license of its LoRAs and a dry compile on its preferred and fallback models (`validatePreset`, also meant for the Studio remix).
- Twelve launch presets (spec §6): 9 drafts join Crash Push, Slow Push and Pan Left. Names and settings are provisional, chosen and tasted in GPU session S2; the combined moves and the tilts wait on session S1 (the core camera node takes one translation pose). The gallery follows the families of the spec with Crash Push first, and the Generate button stays in view however long the gallery gets.
- Every exported video says it is AI-generated: each finished clip is copied (no re-encode) to `data/generations/<id>/clip.mp4` with the MP4 tags `comment = AI-generated` and a one-line `description`, and the sequence film and its 9:16 cut carry the same tags; source tags are dropped. FFmpeg is now checked before a single-shot render (503 `ffmpeg-missing`, no GPU second spent); if tagging fails after the render, the clip is still delivered, untagged, and the error is logged.
- Backend `local` (`MONTAGIO_BACKEND=local`): `ComfyBackend` runs the compiled workflow through `@comfyorg/sdk` 0.5.0 on a self-hosted comfy-api-proxy at an explicit `COMFY_BASE_URL` (Comfy-hosted URLs refused, every SDK request held to that origin, `COMFY_API_KEY` never sent). The start image is uploaded as an asset, a job is read back by id (an app restart does not lose a render), the clip is downloaded once under `data/comfy-outputs/`, and failures surface as stable codes, never pod paths. A fake comfy-api-proxy (`@montagio/comfy-adapter/testing`, CLI `npm run fake-proxy -w @montagio/comfy-adapter -- --port N --clip <mp4>`) backs the tests; no test against the real proxy before GPU sessions S1/S2.
- The Studio runs in `local` mode end to end: `MONTAGIO_BACKEND=local COMFY_BASE_URL=<proxy> npm run dev -w @montagio/web` sends the start image as an asset and the compiled workflow through the Comfy SDK; a workflow ComfyUI refuses answers 422 `workflow-rejected` (details in the server log), an unreachable proxy 503 `backend-unavailable`, an unusable answer 502 `backend-error`, and a sequence stops with the same stable code. `npm run e2e:local -w @montagio/web` drives the Studio against the fake proxy (CI runs it after the demo e2e). S1 checklist: optional box to run the app on the pod.
- Remix a preset in the Studio: "Remix preset" (under the gallery, or on a finished clip) swaps the gallery for a YAML editor prefilled with the preset. "Check preset" runs the same checks as `montagio preset validate` on the chosen model (`POST /api/presets/validate`) and lists the problems line by line; "Download YAML" saves the edited text in the browser; "Generate remix" sends the text, which the server validates again, compiles and keeps next to the render (`data/generations/<id>/preset.yaml`). A preset is 16 KiB of UTF-8 at most (413), larger bodies are refused before they are read, and YAML alias bombs are refused in milliseconds.
- Review fixes for the local mode and the remix: a proxy or tunnel that drops mid-render no longer makes the Studio give up (it keeps polling and picks the render up when the proxy is back), SDK redirects are followed only within the proxy origin, a clip gone from the proxy or an unknown job status ends the job instead of polling forever, and the Studio names the refusals a user can act on (FFmpeg missing, workflow refused by ComfyUI, ComfyUI unreachable; FFmpeg is now listed in CONTRIBUTING). The remix check result is announced to screen readers.
- End-to-end tests: every route is compiled once before the first test (cherry-picked from `fix/e2e-cold-compile`), and the demo e2e runs on one worker, so spec files no longer compete for the CPU of a loaded machine.

## 2026-10-18

- Points the plan 2b review had deferred. The result's "Remix preset" reopens a past remix with its own text (`GET /api/generations/<id>/preset`), goes back to the editor only when it holds that generation's preset, and asks before replacing unsaved edits of another preset; a check result shows only for the model it ran on, and a remix over 16 KiB puts the focus back in the editor. The local backend gives up on a clip download after two minutes (no partial file left, retried on the next poll), keeps only the downloads in flight, and forgets an idempotency key after the web layer's 10-minute window (one shared `IDEMPOTENCY_WINDOW_MS`). The S1 box says it needs `feat/plan-2b` (or its merge into `main`) and keeps `next dev` on 127.0.0.1. New tests pin the reuse of an existing `clip.mp4`, a single tagging under concurrent polls, the speed on the bound node of a remix and the factory's `comfy-outputs` folder; the adapter tests no longer leave temporary folders behind.
- Three leftovers of the same kind: the demo backend also forgets an idempotency key after the 10-minute window, so a key reused later starts a new render instead of handing back the old job; the web server remembers a clip tagging only while it runs (afterwards `clip.mp4` on disk is the record, and a clip removed after delivery is tagged again); the web tests remove their `montagio-web-*` data folder after each test.
- GPU session S1 is replaced by an analysis done without a GPU on the user's laptop (`docs/S1_ANALYSE.md`, in French); session S2 (21–22/10) becomes the first GPU session, with its guide `docs/S2_CHECKLIST.md` (the S1 checklist, rewritten). No weight was downloaded and nothing was generated.
- Licenses read at the source for every weight of the lock, the LightX2V/Lightning repositories and the Comfy-Org workflow templates (card, API license, license file, exact sentence, verdict). All are Apache-2.0 or MIT with no added condition. The Comfy-Org 4-step LoRAs are byte-identical to `lightx2v/Wan2.2-Lightning`; they stay out of the lock until S2 checks the camera motion.
- Exact weight lock: `registry/models.lock.yaml` gives the `resolve/main` URL, the size and the sha256 of all nine files, read from the Hugging Face API (`lfs.oid`) with `fetch-weights --lock-from-hf`; a file whose sha256 or size no longer matches the lock fails before any download. `fetch-weights --inspect <url>` reads only the header of a `.safetensors` file (two Range requests).
- Wan 2.2 5B keeps the camera in the prompt: the header of `Wan2.2-Fun-5B-Control-Camera` (`in_dim` 100, a ×16 camera adapter) matches no model class of ComfyUI v0.41.0, and the core camera nodes work on 16-channel latents.
- Real workflows: `workflows/*.api.json` are converted from the official ComfyUI templates (Comfy-Org/workflow_templates, MIT) through the `/object_info` of ComfyUI v0.41.0. Fun Camera gains `ModelSamplingSD3` (shift 8), the 5B runs image to video, and Z-Image-Turbo is flattened from its subgraph. Bindings follow the template node ids; `ModelSamplingSD3`, `ModelSamplingAuraFlow` and `ConditioningZeroOut` join `allowed-nodes.yaml`. `checkWorkflow` now also checks input names, required inputs, links and dynamic combos, and `infra/runpod/test/workflows.test.ts` checks every workflow and every compiled preset offline against a fixture cut from the real `/object_info`.
- Combined camera moves: the new node "Montagio Camera Embedding" (`comfy-nodes/`) takes `WanCameraEmbedding`'s inputs plus a second move and `combine` (`together` or `then`), and reuses the core's Plücker computation. A preset may say `camera.combine`; `compile.ts` sends a two-move preset to this node instead of joining the poses with " + " (which ComfyUI refuses), and a one-move preset keeps the core node. Push & Settle now pushes then holds; Breathing zooms in then out. The rolls `roll_ccw` and `roll_cw` join the preset schema.
- Checked on a CPU install of ComfyUI v0.41.0 (outside the repository, empty model files named as in the lock, no generation): 0 partner node, the three workflows and ten compiled presets pass `POST /prompt` validation, and the new node gives exactly the core node's tensor for every single move.

## 2026-10-19

- Local installer: `./montagio.sh install` on Linux, `powershell -ExecutionPolicy Bypass -File .\montagio.ps1 install` on Windows (guide: `docs/INSTALL.md`). It checks the machine first (NVIDIA GPU with 24 GB, driver CUDA version, Python 3.10–3.13 with venv, Node.js 22.18+, git, FFmpeg, free disk, RAM, ports) and prints the command that fixes what is missing; below 24 GB it offers the app alone (demo mode, or a remote GPU through `--proxy-url`). It then installs ComfyUI v0.41.0 (commit checked, cloned to a temporary folder first), PyTorch 2.14.1 cu130 (2.11.0 cu128 on older drivers) in its own venv, comfy-api-proxy 0.1.6, links the node pack, fetches the weights of the lock through `infra/runpod/fetch-weights.ts` (resume, sha256), runs `npm ci`, `check-open-stack` and `next build`, then starts ComfyUI with `--disable-partner-nodes`, the proxy and the app on 127.0.0.1 and opens the browser. Each step leaves a stamp in `install-state.json`, so running it again after an update or an interruption redoes only what changed. `start`, `stop` and `status` drive the three services; a pid is only stopped when its command line names this install. `--dry-run` prints every step with its exact commands and changes nothing.
- The installer core (`infra/local`, Apache-2.0) is TypeScript that bare Node.js 22.18+ runs without any npm package, so it checks the machine before `npm ci`; its versions come from `infra/runpod/versions.env`, and its lock reader is tested against the registry's own parser. comfy-cli was weighed and left out (two telemetry SDKs, ComfyUI-Manager by default, no pinned PyTorch).
- Checked on the user's laptop (Windows 11, RTX 3050 4 GB, no PyTorch CUDA install, no weight downloaded): the three dry runs (refusal with the app-only offer, full plan with `--ignore-vram`, app only), a real start and stop against a CPU ComfyUI v0.41.0 outside the repository (650 node classes, 0 partner node, Montagio Camera Embedding loaded, Studio served by `next start`, everything stopped in 3 s), and a real `install --app-only` through `montagio.ps1` (npm ci, check-open-stack, next build, start: 4 minutes; run again: 11 s, only the open-stack check and a restart).
- An independent review of the installer found, and tests now pin: process command lines read in the console code page on Windows (an accented profile name made `stop` lose the services), a disk check that charged already-downloaded bytes again after an interruption, a weight whose pinned sha256 changes being re-hashed and refused forever, GPUs numbered differently by CUDA and nvidia-smi on multi-GPU machines, and a stamp trusted after its program was removed. Not checked yet: a full install on a 24 GB GPU, and Linux on real hardware. Two findings on the way: R6xx NVIDIA drivers print `CUDA UMD Version` instead of `CUDA Version` (the installer reads both; `infra/runpod/bootstrap.sh` still reads only the old form), and on Windows the services inherit a piped output from PowerShell, so a redirected `start` returns only at `stop` (documented).
